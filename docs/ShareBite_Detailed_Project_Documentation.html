Chapter 1: Introduction & Project Background

1.1 The Real-World Problem of Food Waste

Every single day, weddings, restaurants, corporate cafeterias, bakeries, and university hostels prepare food for large numbers of people. Because customer numbers fluctuate, commercial kitchens routinely have surplus portions left over at the end of every meal service. At the very same time, millions of underprivileged people, homeless shelters, orphanages, and community kitchens struggle every day to feed hungry children and families.

The problem is not that there is no food. The problem is the lack of a real-time, fast, and trustworthy communication bridge between the food business that has extra food and the nearest charity that can distribute it before it spoils.

1.2 The ShareBite Solution

ShareBite is an intelligent, full-stack web platform designed to solve this problem in minutes:

  • Instant Food Posting: A restaurant manager can post surplus food in under 30 seconds. The app uses browser GPS to automatically fill the physical address.
  • Live Interactive Map: Nearby NGOs and volunteers instantly see available food on an interactive Leaflet radar map with color-coded markers.
  • Safe Handover via 6-Digit OTP: To prevent food theft or wrong deliveries, the system generates a 6-digit OTP when an NGO claims a batch. The donor checks this OTP before handing over the food.
  • Automated Food Safety Sweeper: A background timer checks every 60 seconds. Any food that passes its safe consumption time is automatically marked as expired so nobody gets sick.

5.1 Dual-Mode Storage Architecture (`server/src/db.js`)

One of the most powerful features of ShareBite is its Dual-Mode Storage Engine. When the application boots up, it checks if a live PostgreSQL database URL is configured. If PostgreSQL is online, it connects using a connection pool. However, if PostgreSQL is offline or not installed, ShareBite does not crash. Instead, it automatically switches to an internal, high-fidelity in-memory database store (fallbackStore). 

// From server/src/db.js: Dual-Mode Connection Initialization
async function initDatabase() {
  const connectionString = process.env.DATABASE_URL || null;

  if (connectionString) {
    try {
      pool = new Pool({
        connectionString,
        connectionTimeoutMillis: 5000, // 5-second connection guard
      });
      // Test the connection
      const res = await pool.query('SELECT NOW() as current_time;');
      usePostgres = true;
      console.log(`[Database] Connected to PostgreSQL at ${res.rows[0].current_time}`);
      await runMigrations(); // Automatically create tables if missing
    } catch (err) {
      console.warn(`[Database] PostgreSQL connection failed: ${err.message}`);
      console.warn('[Database] Running with high-fidelity in-memory database store.');
      usePostgres = false;
    }
  } else {
    console.log('[Database] No DATABASE_URL provided. Running with in-memory store.');
    usePostgres = false;
  }
}
How this works: The code creates a Pool using the pg library with a 5000 ms timeout. If the database responds, usePostgres is set to true. If it fails or times out, the catch block intercepts the error, sets usePostgres = false, and allows the server to run smoothly in memory.

5.4 Detailed Code Logic: Atomic Food Claiming & 6-Digit OTP Generation

When an NGO claims food, two critical operations occur: locking the listing to prevent duplicate claims, and generating a cryptographically random 6-digit OTP. 

// From server/src/db.js: claimListing()
async claimListing(id, claimer) {
  // Generate a random 6-digit number between 100000 and 999999
  const otp = crypto.randomInt(100000, 999999).toString();
  const claimedAt = new Date().toISOString();

  if (usePostgres) {
    // Parameterized SQL query: atomic update with conditional WHERE clause
    const res = await pool.query(
      `UPDATE listings
       SET status = 'claimed',
           claimed_by = $1,
           claimed_by_id = $2,
           otp = $3,
           claimed_at = $4
       WHERE id = $5 AND status = 'pending' AND expires_at > NOW()
       RETURNING *;`,
      [claimer.name, claimer.id || 'ngo-anon', otp, claimedAt, id]
    );
    if (res.rows.length === 0) return null; // Already claimed or expired!
    return formatListing(res.rows[0]);
  }

  // In-Memory Fallback Engine
  const listing = fallbackStore.listings.find((l) => l.id === id);
  if (!listing || listing.status !== 'pending' || new Date(listing.expires_at) <= new Date()) {
    return null;
  }
  listing.status = 'claimed';
  listing.claimed_by = claimer.name;
  listing.claimed_by_id = claimer.id || 'ngo-anon';
  listing.otp = otp;
  listing.claimed_at = claimedAt;
  return formatListing(listing);
}
Key Security & Concurrency Logic: Notice the SQL clause WHERE id = $5 AND status = 'pending' AND expires_at > NOW(). This guarantees atomicity: even if two volunteers click "Claim" at the exact same millisecond, only the first request can update the database row. The second request returns 0 updated rows and receives a clean "Already Claimed" response.

5.5 Detailed Code Logic: OTP Verification & Pickup Completion

When the volunteer arrives at the restaurant, the donor enters the 6-digit OTP into their dashboard to complete the physical pickup: 

// From server/src/db.js: verifyPickup()
async verifyPickup(id, submittedOtp) {
  const pickedUpAt = new Date().toISOString();

  if (usePostgres) {
    // Verify OTP matches exactly and listing is currently 'claimed'
    const res = await pool.query(
      `UPDATE listings
       SET status = 'picked_up',
           picked_up_at = $1,
           otp = NULL               -- Invalidate OTP after successful pickup
       WHERE id = $2 AND status = 'claimed' AND otp = $3
       RETURNING *;`,
      [pickedUpAt, id, String(submittedOtp).trim()]
    );
    if (res.rows.length === 0) return null; // Wrong OTP or invalid state!
    return formatListing(res.rows[0]);
  }

  // In-Memory Fallback Engine
  const listing = fallbackStore.listings.find((l) => l.id === id);
  if (!listing || listing.status !== 'claimed' || listing.otp !== String(submittedOtp).trim()) {
    return null;
  }
  listing.status = 'picked_up';
  listing.picked_up_at = pickedUpAt;
  listing.otp = null;
  return formatListing(listing);
}
Security Note: Setting otp = NULL immediately upon pickup invalidates the code permanently. The code cannot be re-used, protecting the food donor from false claims.

5.6 Detailed Code Logic: 60-Second Food Safety Sweeper

To guarantee food safety, the backend runs an automated cron job every 60 seconds using node-cron: 

// From server/src/index.js & server/src/db.js: Automatic Food Safety Daemon
const cron = require('node-cron');

// '* * * * *' = Runs every minute on the 00th second
cron.schedule('* * * * *', async () => {
  try {
    const expiredCount = await db.expireUnsafeListings();
    if (expiredCount > 0) {
      console.log(`[Safety Daemon] Auto-expired ${expiredCount} stale food listings.`);
    }
  } catch (err) {
    console.warn('[Safety Daemon] Sweeper error:', err.message);
  }
});

// The Database Update in server/src/db.js:
async expireUnsafeListings() {
  const now = new Date().toISOString();
  if (usePostgres) {
    const res = await pool.query(
      `UPDATE listings
       SET status = 'expired', expired_at = $1
       WHERE status IN ('pending', 'claimed') AND expires_at < $1;`,
      [now]
    );
    return res.rowCount;
  }
  // Fallback Store
  let count = 0;
  for (const l of fallbackStore.listings) {
    if (['pending', 'claimed'].includes(l.status) && new Date(l.expires_at) < new Date(now)) {
      l.status = 'expired';
      l.expired_at = now;
      count++;
    }
  }
  return count;
}
Why this is crucial for food safety: If cooked food is only safe until 2:00 PM, at 2:01 PM this automated task updates the listing's status to expired. It disappears from the public map, preventing any volunteer from traveling to collect spoiled food.

6.2 Dynamic View Centering with `MapController.jsx`

In standard React, if the parent state changes (for example, when the user clicks "Track My Exact Location" or picks a different city from the dropdown), the Leaflet MapContainer does not automatically re-center because Leaflet manages its own DOM canvas.

To solve this, we created a specialized child controller component using the useMap() React hook: 

// From client/src/components/map/MapController.jsx
import { useEffect } from 'react';
import { useMap } from 'react-leaflet';

export function MapController({ center, zoom = 13 }) {
  const map = useMap(); // Accesses Leaflet's internal L.Map instance

  useEffect(() => {
    if (center && Number.isFinite(center[0]) && Number.isFinite(center[1])) {
      // Smoothly animates the map to the new latitude and longitude
      map.setView(center, zoom, {
        animate: true,
        duration: 0.8, // 800ms smooth pan-and-zoom animation
      });
    }
  }, [center[0], center[1], zoom, map]);

  return null; // Renders no visible HTML element; strictly controls the camera
}
Why this is important: Whenever center coordinates change in state, useEffect executes map.setView(center, zoom). This causes the Leaflet camera to glide smoothly to the user's exact live GPS coordinates.

Chapter 7: External Services & Mathematical Modeling

7.1 Real-World Distance Calculation: The Haversine Formula

Because the Earth is a sphere, the shortest distance between two points is an arc across its surface (the great-circle distance). Flat Pythagorean distance ($d = \sqrt{\Delta x^2 + \Delta y^2}$) causes severe errors over geographic coordinates.

ShareBite implements the spherical Haversine Formula in server/src/db.js:

a = sin²(Δlat / 2) + cos(lat1) · cos(lat2) · sin²(Δlon / 2)
c = 2 · atan2( √a, √(1 − a) )
Distance (d) = R · c (where Earth Mean Radius R = 6,371 km) 
// From server/src/db.js: Haversine Implementation
function distanceKm(lat1, lon1, lat2, lon2) {
  const R = 6371; // Earth's Mean Radius in Kilometers
  const dLat = (lat2 - lat1) * (Math.PI / 180);
  const dLon = (lon2 - lon1) * (Math.PI / 180);
  const a =
    Math.sin(dLat / 2) * Math.sin(dLat / 2) +
    Math.cos(lat1 * (Math.PI / 180)) * Math.cos(lat2 * (Math.PI / 180)) *
    Math.sin(dLon / 2) * Math.sin(dLon / 2);
  const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
  return Number((R * c).toFixed(2));
}

7.2 Live NGO Radar: OpenStreetMap Overpass with 5-Second Abort Controller

Instead of requiring thousands of charities to manually sign up before the platform can work, ShareBite dynamically queries the open-access OpenStreetMap Overpass API: 

// From server/src/services/osmService.js: Live NGO Radar Query
async function fetchNearbyNGOsFromOSM(lat, lng, radiusKm = 15) {
  const radiusMeters = Math.min(Math.max(radiusKm * 1000, 1000), 50000); // 1km to 50km

  // Overpass QL Query: Searches nodes and ways tagged as social facilities, soup kitchens, or charities
  const query = `
    [out:json][timeout:6];
    (
      node["amenity"="social_facility"](around:${radiusMeters},${lat},${lng});
      node["office"="ngo"](around:${radiusMeters},${lat},${lng});
      node["office"="charity"](around:${radiusMeters},${lat},${lng});
      node["social_facility"="soup_kitchen"](around:${radiusMeters},${lat},${lng});
      node["amenity"="food_sharing"](around:${radiusMeters},${lat},${lng});
    );
    out center 25;
  `;

  // 5-Second Abort Controller Timeout Guard
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 5000);

  try {
    const response = await fetch('https://overpass-api.de/api/interpreter', {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: `data=${encodeURIComponent(query)}`,
      signal: controller.signal, // Auto-cancels if server takes > 5s
    });
    clearTimeout(timeoutId);
    const data = await response.json();
    return (data.elements || []).map(formatOSMElement);
  } catch (error) {
    console.warn('[OSM Service] Query aborted or failed; using database fallback.');
    return []; // Gracefully returns empty array; app uses database records
  }
}
Why the AbortController is essential: Public APIs can sometimes be slow. The setTimeout(() => controller.abort(), 5000) guarantees that if the Overpass server does not answer within 5 seconds, the request is cancelled immediately. The backend falls back to its verified database records and the user never experiences a frozen screen.

7.3 Nominatim Reverse Geocoding

When a user's phone supplies raw GPS coordinates (e.g. lat: 12.9352, lng: 77.6245), users cannot easily read numbers. ShareBite calls OpenStreetMap Nominatim to convert coordinates into human-readable physical addresses: 

// From server/src/services/osmService.js: reverseGeocode()
async function reverseGeocode(lat, lng) {
  const url = `https://nominatim.openstreetmap.org/reverse?lat=${lat}&lon=${lng}&format=json`;
  const res = await fetch(url, {
    headers: { 'User-Agent': 'ShareBite-FoodRecovery/1.0' }
  });
  const data = await res.json();
  return {
    displayName: data.display_name || `${lat.toFixed(4)}, ${lng.toFixed(4)}`,
    road: data.address?.road || '',
    suburb: data.address?.suburb || data.address?.neighbourhood || '',
    city: data.address?.city || data.address?.town || '',
  };
}
